# 협업 구조 — 기획 · 디자인 · 개발

작성일: 2026-10-23. 삼국히어로즈를 《우르르 용병단》 원작 분석 결과 위에서 만들기 위한 역할·폴더·파일 규칙이다.
[AGENTS.md](../AGENTS.md)의 디자인 지침과 **공격·스킬·모션 제작 보류 결정은 이 문서보다 우선한다.**

## 1. 역할과 산출물

| 역할 | 하는 일 | 기준 자료 | 산출물 위치 |
|---|---|---|---|
| 기획자 | 유닛·스킬·성장·시나리오 기획, 원작 대비 변경점 결정 | 원작 카탈로그(xlsx), 맵 메이커 시뮬레이션 | `docs/planning/`, `content/samguk/*.json` |
| 디자이너 | 캐릭터·지형·오브젝트·UI 그림 | [기본 스타일](design/SAMGUK_BASE_STYLE.md), 승인 7컷, 맵 메이커 v3 화면 | `art/samguk/` |
| 개발자 | 원작 엔진·리소스 모듈, 맵 메이커·시뮬레이터, 팩 로더 | 원작 분석(별도 로컬 저장소 `sam_heros2`) | 로컬 `sam_heros2/web` |

작업 순서는 **기획 → 맵 메이커에서 원작 리소스로 검증 → 디자인 → 같은 맵에서 신규 그림으로 재검증**이다.
그림이 없어도 기획 데이터만으로 시뮬레이션할 수 있고, 그림이 생기면 같은 키로 자동 교체된다.

## 2. 폴더 구조

```
sam_heros/
├─ AGENTS.md                    디자인 지침·보류 결정 (최우선)
├─ README.md                    프로젝트 현황
├─ docs/
│  ├─ COLLABORATION.md          이 문서
│  ├─ design/                   승인 스타일·목업·원작 근거 (기존, 덮어쓰기 금지)
│  └─ planning/                 기획 문서
│     ├─ README.md              기획 작업 규칙
│     ├─ catalog/               원작 유닛·스킬 카탈로그 xlsx (로컬 전용, git 제외)
│     ├─ units/<유닛ID>.md      유닛 기획서 (템플릿: templates/unit.md)
│     ├─ scenarios/<장>.md      시나리오·스토리 (템플릿: templates/scenario.md)
│     └─ templates/
├─ content/samguk/              게임이 읽는 데이터 (기획자가 편집, 맵 메이커가 읽고 씀)
│  ├─ pack.json                 팩 정의
│  ├─ units.json                유닛 정의 — 원작 base 유닛 + 변경점
│  ├─ maps/<맵이름>.map.json    맵 메이커 저장 파일 (메이커 "저장" 버튼이 여기로 저장)
│  └─ scenarios/                시나리오 데이터 (예정)
└─ art/samguk/                  디자이너 산출물 (규격: art/samguk/README.md)
   ├─ units/<유닛ID>/           icon.png, portrait.png, (모션 재개 후) frames/
   ├─ tiles/                    지형 타일
   ├─ objects/                  건물·울타리·바위·나무 등
   ├─ effects/                  이펙트 (모션 보류 중 — 제작하지 않음)
   └─ ui/                       UI 조각
```

원작 리소스(스프라이트·테이블·사운드)는 이 저장소에 넣지 않는다. 개인 로컬 분석용이며, 최종 제품은 `art/samguk`의 자체 그림만 사용한다.

## 3. ID와 이름 규칙

| 대상 | 형식 | 예 |
|---|---|---|
| 삼국 유닛 | `SG_U####` | `SG_U0001` 유비 |
| 삼국 스킬 (신규 정의 시) | `SG_S####` | `SG_S0001` |
| 맵 | 한글 가능, 파일명 `<이름>.map.json` | `1장_황건소탕.map.json` |
| 원작 참조 | 원작 키 그대로 | `Unit000001`, `Skill001000` |

한 번 쓴 ID는 바꾸지 않는다(맵 파일과 그림 폴더가 ID로 연결된다). 이름은 언제든 바꿔도 된다.

## 4. 유닛 정의 (`content/samguk/units.json`)

```json
{
  "id": "SG_U0002",
  "name": "관우",
  "grade": "전설", "gradeType": "LEGEND",
  "base": "Unit000011",
  "statKey": "UnitStat011000",
  "levels": [
    { "level": 1,  "defaultSkill": "Skill011000", "skillA": "Skill011001" },
    { "level": 20, "skillA": "Skill011002" },
    { "level": 40, "skillB": "Skill024003" }
  ],
  "art": { "icon": "art/samguk/units/SG_U0002/icon.png", "portrait": "art/samguk/units/SG_U0002/portrait.png" },
  "memo": "기획 메모"
}
```

- `base` (필수): 모션·크기·기본 능력치·스킬을 빌릴 원작 유닛. 카탈로그 **유닛** 시트에서 고른다.
- `statKey` (선택): 능력치 곡선만 다른 원작 유닛의 것으로 바꾼다 (카탈로그 유닛 시트 기준).
- `levels` (선택): 표시 레벨별 스킬 구성. 지정한 칸만 바뀌고 나머지는 base 그대로다. 스킬 키는 카탈로그 **스킬** 시트에서 고른다. 생략하면 base의 레벨별 스킬을 그대로 쓴다.
- `art` (선택): 그림이 있으면 메이커 팔레트·인스펙터에 표시, 없으면 base 원작 아이콘으로 대체.
- 원작에 없는 새 스킬 동작이 필요하면 `docs/planning/units/<ID>.md`에 "신규 스킬 요청"으로 적는다. 개발자가 엔진 데이터로 옮긴다. (모션 보류가 풀리기 전에는 원작 스킬 조합으로만 기획한다.)

## 5. 맵 파일 (`content/samguk/maps/*.map.json`)

맵 메이커가 만든다. 사람이 직접 고칠 일은 드물지만 구조는 다음과 같다.

- 원작 월드 맵(`World_*.bytes`)과 같은 레이어: `mapData`(잔디) `roadData`(흙길) `waterData`(물) `decoData`(바위·울타리) `blockData`
  - 좌표는 아이소메트릭 칸. 지형 칸 3.32×2.0 월드 단위, 장식 칸은 그 1/3.
- `maker.units[]`: `{ id, key, team: "ally"|"enemy", level, x, y }` — `key`는 `SG_U####` 또는 원작 `Unit######`, `level`은 화면 표시 레벨.
- `maker.trees[]`: `{ id, x, y }`

## 6. 맵 메이커 · 시뮬레이터 사용법

1. 로컬 저장소 `sam_heros2`에서 `python tools/serve.py 8124` 실행. 이 저장소는 자동으로 `/samguk/`에 연결된다(경로가 다르면 환경 변수 `SAMGUK_REPO`).
2. http://127.0.0.1:8124/web/maker.html 접속 (v3 시안 레이아웃).
3. **편집**
   - 왼쪽 지형(잔디·흙길·물·바위·나무·울타리)을 고르고 그리기로 칠한다.
   - 유닛 탭: 삼국 / 영웅 / 용병 / 몬스터 / 기타. 검색할 수 있다.
   - 유닛을 고르고 클릭하면 배치된다. 오른쪽에서 진영·레벨을 바꾸고, 레벨별 스킬 해금 상태를 확인한다.
   - 조작:

     | 조작 | 동작 |
     |---|---|
     | 휠 | 확대·축소 |
     | 가운데/오른쪽 드래그 | 화면 이동 |
     | 1 / 2 / 3 | 선택 / 그리기 / 지우기 |
     | Delete | 삭제 |
     | Ctrl+Z | 되돌리기 |

4. **▶ 실행**
   - 게임 카메라(원작 기본 배율)로 고정된다. 클릭한 곳으로 아군 부대가 이동하고, 공격·스킬은 원작 규칙대로 자동 발동한다.
   - 화면에 아군 전멸 / 적군 전멸이 표시된다.
5. **편집으로**: 실행 전 배치와 확대 비율이 그대로 돌아온다.
6. **저장**: 서버가 이 저장소를 연결하고 있으면 `content/samguk/maps/<맵이름>.map.json`에 바로 저장된다. 연결되어 있지 않으면 파일로 다운로드된다. **불러오기**는 `.map.json` 파일이나 원작 맵 `.bytes` 파일을 연다.

## 7. 기획 ↔ 디자인 연결 흐름

1. 기획자가 `units.json`에 유닛을 추가한다(ID 발급, base 선택). `docs/planning/units/<ID>.md`에 콘셉트·역할·스킬 구성을 쓴다.
2. 메이커에서 base 그림으로 전투를 돌려 보며 레벨·스킬 구성을 조정한다.
3. 디자이너가 `docs/planning/units/<ID>.md`와 승인 스타일을 보고 `art/samguk/units/<ID>/`에 그림을 넣는다.
4. 메이커를 새로고침하면 팔레트에 새 아이콘이 보인다. 같은 맵에서 크기·가독성을 확인한다.
5. 바꾼 점은 각 문서의 "변경 이력"에 날짜와 함께 적는다.
