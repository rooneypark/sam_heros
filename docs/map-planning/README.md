## 정리·협업 원칙

- 전체 규칙은 이 폴더 바로 아래, 유닛은 `units/`, 시나리오는 `scenarios/`에 저장한다.
- 최신 확정 기획만 유지한다. 폐기·미채택안, 과거 버전 비교, 임시 개발 수치, 이전 변경 내용은 삭제하며 별도 기획 백업·아카이브를 만들지 않는다.
- 새 결정을 저장할 때 이전 설명을 교체한다. 과거 결정을 같은 문서에 누적해 여러 버전이 공존하게 하지 않는다. 문서의 최신 정리일은 갱신한다.
- 미정 항목은 질문으로 분리한다. 미승인 제안을 확정 사양이나 수치로 적지 않는다.
- 기획 확정은 구현·검증 완료를 뜻하지 않는다. 개발 상태가 필요하면 현재 상태만 확인하며 시험값을 기획값으로 승계하지 않는다.
- 기획자는 문서만 작성한다. 게임·엔진·맵 메이커·실행 데이터·수치 오버라이드를 직접 수정하지 않는다. 이 원칙은 후속 작업에도 계속 적용한다.
- 개발자에게 전달할 때 공통 원본 경로를 사용한다. 별도 메시지는 사용자 요청 시에만 발송한다.

## 원작 참고 자료·양식

[GAME_SYSTEMS.md](GAME_SYSTEMS.md)와 `catalog/`의 두 데이터북은 원작 분석 참고 자료다. 이전 삼국 기획 버전이 아니며 신규 확정 사양으로 사용하지 않는다. 삭제·수정하지 않았다.

`templates/`는 신규 기획 작성용 양식이며 확정 사양이 아니다. 새 문서에 예시 레벨·수치·패턴을 그대로 확정값으로 옮기지 않는다.
